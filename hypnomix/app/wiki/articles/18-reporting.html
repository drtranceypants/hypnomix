HypnoMix has no server of its own and never phones home: no usage data, no automatic crash reports, no account. When something goes wrong it writes a report here, on your computer, shows it to you word for word, and helps you send it yourself to the project's public issue tracker (or anywhere else: it is plain text). If you do nothing, no report, song or setup leaves your computer. The app does ask the internet for two things, and only those: GitHub's list of releases (to tell you when a new version is out) and the website's list of Wiki articles (to keep the Wiki current); neither request carries a report, a song or your setup.

How to write one

  • In the app: click Report a problem at the top right, or Report this on any error message, failed job or the crash notice. A window opens with two boxes (What happened? and What did you expect?), a few choices, and a live preview of the exact report; it changes as you type.
  • In a terminal: hypnomix report prints the report it would share and writes nothing. --what "..." and --expected "..." fill in the two parts only you can write.
$ hypnomix report --what "the review page stayed empty after a scan" --expected "the findings"
$ hypnomix report --crash                 # the newest crash record, as a report
$ hypnomix report --list                  # every crash record on this computer
$ hypnomix report --out report.md --copy    # save it as a new file, and copy it
$ hypnomix report --copy --open            # copy it, then open the issue page: paste it there

What is in a report

  • The two parts you write, if you write them.
  • The HypnoMix version, how it is installed (the Mac or Windows app, pip, or a source checkout), your operating system and version, the Python version, and the DAW you chose in Setup.
  • The versions of three Python packages HypnoMix reads audio with (numpy, scipy and soundfile), or that one is not installed.
  • Which helpers are there: ffmpeg and the stretch program (Rubber Band), present or not. Never where they are.
  • The last command or job and how it ended (for a command, only when it ended with an error).
  • Each of these is a separate choice you can switch off: the end of the last job's log (the last 60 lines), the last crash record, and how many findings each tool made in the open scan (counts only).
  • Environment variables are never listed. The report names only a fixed list of HypnoMix's own switches (such as HYPNOMIX_DEBUG) and says whether each is set, never its value.

What is hidden from it

HypnoMix hides these as far as it can tell: it matches the shapes of paths and keys and the names the open scan knows, so it can miss one. Known misses: a folder name with an apostrophe, a quote, a question mark, a comma or a bracket in it can leave a piece of the name behind; a name is matched in the spelling the scan has (a different capital letter, or a space written as an underscore, is a different spelling); a track name in plain error text that the scan does not know stays in; and a secret written as name=value under a name that does not look like a secret's name is not hidden. Read the report before you share it, and change anything you do not want to show.

  • Your home folder is written ~. Every other path is cut down to a placeholder with the extension kept: <file 1>.wav. So is a bare file name with no folder in front of it ('Lead Vocal.wav' in an error message, the way Python quotes a file it could not open). The same name is always the same number inside one report.
  • Song, project, track and clip names that the open scan knows are replaced the same way: <track 3>. Turn on Keep names (--names) if you think the names help; then a path keeps its file name and known names stay. The default is off.
  • API keys and tokens: the keys saved for the Assistant, any secret in your environment, and anything shaped like a key (including web tokens, cloud key ids and Authorization headers), are replaced by <hidden>. Email addresses and the user name in an address such as ssh://user@host are hidden too. This holds even with Keep names on.
  • No audio, no project files, no settings, no list of your folders.

This is done by looking for paths, keys and the names it knows, so it can miss something it cannot recognise (a song title typed in a sentence, say). Read the preview before you share it, and take out anything private. The same scrubbing is applied to what you type in the two boxes.

How to send one

Reports go to the project's public issue tracker at github.com/drtranceypants/hypnomix/issues. Anything posted there is public. The three buttons:

  • Copy the report: puts the text on your clipboard.
  • Save as a file: writes a new file (hypnomix-report-….md) into the app's work folder, under reports, and can show it in its folder. An earlier file is never replaced.
  • Copy it and open the issue page: copies the report, then opens the new-issue page in your browser. You paste it there and press the button yourself. The page is opened with the template's name only: no word of the report is ever put into a web address.

The issue form has matching sections, so a pasted report fits. Or send the file by any other way you like. HypnoMix never contacts the tracker, a DAW or any server while it writes a report.

Crash records

When HypnoMix hits a bug it did not expect, it saves a crash record and says so in one sentence; nothing is sent. In a terminal the command ends with that sentence and exit code 70, and hypnomix report --crash shows it and how to send it. In the app a quiet notice appears at the top (See it, Report it, Dismiss); it never takes the focus. A record from an earlier run is offered once, the next time the app starts. A mistake in the app's own page (including the DAW view, whose status bar has a Report a problem link that opens the dialog) is recorded the same way, a few a minute at most. In the app, an error in a request or a job, or a failure while the app starts, is a bug and leaves a record; an answer the app gives on purpose ("that file is not a Live set", a missing or wrong field in a request) is a plain sentence and does not.

  • What a record holds: the version, platform, the command's name, the names of the options you gave with each value replaced by its kind (--mix <path>, --bpm <number>), the kind of error and its message, and the steps of the traceback with file names inside HypnoMix only. Scrubbed the same way as a report.
  • Where they live: the crashes folder inside the HypnoMix home (~/.hypnomix/crashes, or %USERPROFILE%\.hypnomix\crashes on Windows; HYPNOMIX_HOME moves it). One small JSON file each.
  • How many: the newest 20 are kept; the older ones are removed. Disk care lists the folder with its size.
  • How to delete them: delete the files (or the whole folder) in a file manager. Nothing else needs them. Dismiss in the app only hides the notice.
  • Seeing the traceback itself instead: run the command again with HYPNOMIX_DEBUG=1.

The Assistant

The Assistant may run hypnomix report and hypnomix report --crash or --list on its own: they only read and print. Anything that saves a file, copies, or opens a page (--out, --copy, --open), or fills in the report's words, asks for your click like every other command that writes.
