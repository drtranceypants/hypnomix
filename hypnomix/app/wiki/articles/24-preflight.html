Half of "my mix sounds wrong" is a file problem: one stem at 48 kHz in a 44.1 kHz session, a stem exported a second late, a vocal that is really an mp3, a file the project cannot find. preflight checks all of that first. It only reads.

$ hypnomix preflight "Song stems/"
$ hypnomix preflight "Song.rpp"                # or Song.als, Song.ardour, an Ardour session folder
$ hypnomix preflight "Song stems/" --plan   # the same findings, in a scan folder for the normal review

For a folder it reads every audio file in it (--recursive for the folders inside). For a set or project it reads every source file the project plays, through the shared project model, so Live, REAPER and Ardour work the same way.

What it looks for

  • Sample rate and bit depth that differ from the rest, and which files are the odd ones out (with no clear majority it says so).
  • Length and start (folders): stems of one song that differ in length (--length-tolerance), or whose sound arrives ahead of or behind the others (found by lining up their loudness shapes; --max-lag sets how far it looks). Stems that play different parts match each other weakly, so it only speaks when the match is good and clearly better than lined up: a near-perfect match is a high finding, a good one is "check by ear". On a steady rhythm it names the nearest lag and says it may be a whole number of beats off. A project's clips are placed by position, so they are not compared.
  • Exact duplicates: two files with identical audio under different names.
  • Fake stereo (left equals right, judged against the file's own peak, so a very quiet stereo file is not called mono), a stereo file with one empty channel, and a list of the mono files.
  • Silent or nearly silent files, DC offset, and files that are already clipped.
  • Broken files: NaN or infinite samples (a plug-in that blew up while exporting; the first one is named by its time), and files with more than five channels, which the measuring tools do not read.
  • Lossy sources (mp3, aac and friends) in a project.
  • Missing or offline files, with the tracks that need them.
  • Names that will not survive another system: characters Windows refuses, reserved names, a trailing space or dot, names that differ only by capitals, very long names and paths.

Each is a finding with what to do. Nothing is renamed, moved, converted or deleted: it tells you which file and what to change. The report is PREFLIGHT.md, in hypnomix-out/preflight/<name of the source> (--out picks the folder); an earlier report is never overwritten: a second run gets <name> (2), and an --out folder that already holds a report is refused. The exit code is 1 when something high turns up (a missing file, a stem that starts apart, heavy clipping), so a script can stop on it.

With --plan

Every finding goes into a scan folder and through the usual review. The three that prep already repairs are planned as prep steps: DC offset (rumble), flat-topped peaks (declip) and fake stereo (mono); fix --approved writes only the approved ones as new files (prep also puts its usual short fades on the ends of those files). Mixed rates, bit depths and lengths are made uniform by hypnomix prep FOLDER --plan (its format step); the rest, such as re-exporting a stem or finding a file, are yours to do.

Measured, not heard. A file it calls silent may be an empty track on purpose: say so and skip it. Run it before scan; the scan then works on files that are fit to be scanned. See also refs (missing files in a Live set only).
