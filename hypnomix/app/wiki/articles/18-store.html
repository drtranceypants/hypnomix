Mac only for now. The Store installs into the Mac's Library and Music folders. On another system the Store tab and the hypnomix store command say so plainly and install nothing; the free plug-ins can still be downloaded from their publishers' own pages (each item's Details links to it).

The Store tab in the app is a short, checked list of free plug-ins and sounds, each downloaded from its publisher's own page or GitHub releases. Search it, filter it by kind (effect, instrument, synth, drum kit, sample pack, SFZ instrument), format (VST3, AU, CLAP, LV2, SFZ, WAV) and licence, open an item's Details to read its licence and see exactly where it comes from, then press Install. In the DAW view, the browser's Store place opens it too.

What happens when you press Install

  1. The newest download is found: for GitHub items, the newest release file that matches the catalogue; for the others, the publisher's fixed link.
  2. It is downloaded over HTTPS only (a redirect to anything else is refused, and a token is never sent on to another site). When there is a sha256 fingerprint to check against, the download is checked against it, and a mismatch deletes it. See Is it verified? below. The download also has limits: it may not be much bigger than the size the catalogue states (or 2 GB when none is stated), the whole install must finish within four hours, the disk must have room for the download, its unpacked copy and the installed copy, and a Cancel button stops it.
  3. It is unpacked (zip, tar, 7z, or a disk image opened read-only and closed again). Paths, and links, that would land or point outside the folder are refused, disk images included, and so is an archive that unpacks to far more than it weighs (more than 100 times its size, 20 GB in all, or 100,000 files; what an unpack writes is measured about once a second while it runs, and once more when it ends, so a fast one can land before it is stopped; the disk-space check before the download keeps that bounded). On a Python that lacks the safe-extraction filter (older than the security releases of 3.11, in a terminal), a tar archive with any link in it is refused outright. Nothing in the download is run.
  4. Plug-ins are copied into ~/Library/Audio/Plug-Ins/ (VST3, Components for AU, CLAP, LV2). Sounds go into ~/Music/Hypnomix Library/ (Drum Kits, Sample Packs, SFZ Instruments), one folder per item.
  5. The app writes down every file and folder it put there, so Uninstall removes exactly that and nothing else, and Update replaces it.

Is it verified?

Each item's Details says how its download can be checked, before you press Install:

  • Pinned: the catalogue holds the sha256 the publisher gave. No item is pinned yet.
  • GitHub's fingerprint: the items downloaded from GitHub releases are checked against the sha256 GitHub publishes for the release file, when it publishes one. That catches a damaged or swapped download; it does not prove the publisher's account was not compromised.
  • Not verified: three items are fixed links with no fingerprint to check (the Salamander Grand Piano, VSCO 2 CE and the Versilian Community Sample Library). They carry a not verified tag. Any download with nothing to check it against, whichever item, is not installed until you confirm a second time, in plain words, that it is not verified: a button in the Store tab ("Install anyway (not verified)"), --unverified on the command line, and the same words on the Assistant's approval card.

Installer packages

Some publishers only ship an installer package (.pkg): OB-Xd, Odin 2, Cardinal, Airwindows Consolidated, Dragonfly Reverb, the CHOW plug-ins, Valentine, Wolf Shaper and sfizz. The store never runs those for you. It downloads the package, marks it as downloaded from the internet (so that macOS checks it when it opens), opens it in Apple's Installer, and you read it and click through it yourself. An installer package puts files outside your home folder and asks for your password, which is why the Store never does it for you. Show installer opens it again later; Disk care clears kept installers after 30 days (sooner on a nearly full disk), and then the button is gone until you install again. Remove those plug-ins with the publisher's instructions; Forget only deletes the kept installer. Not tried: opening a real publisher's installer package through macOS's check on this build.

An item whose publisher's site doesn't allow automatic downloads gets a Get it from button that opens its download page instead.

When something is already there

If a plug-in with the same name is already installed and the store didn't put it there (you installed it yourself, say), the install stops and lists what is in the way. Replace them goes ahead after you confirm, and moves the old copies to ~/.hypnomix/store/trash rather than deleting them at once (Disk care clears the trash after 60 days). Disk care clears that trash, unfinished downloads and old kept installers quietly, like its other caches: trash after 60 days, kept installers after 30, leftovers of a stopped download after 2 (all sooner when the disk is nearly full).

Uninstall

Uninstall removes exactly the paths the app wrote down, and only if each is one item directly inside a plug-in or sounds folder (compared by real path, so a link cannot lead it elsewhere, and a whole plug-in folder is never removed). If the list has been edited by hand to point anywhere else, nothing is removed and it says so.

After installing

Your DAW finds new plug-ins the next time it starts or rescans them. If the Hypnomix DAW's engine is connected the store asks it to rescan, but its MCP surface has no rescan tool yet, so the app tells you to rescan in the DAW's Plugin Manager or restart it. SFZ instruments and drum kits play in sfizz, which is also in the store: load the .sfz file from the item's folder.

Licences

Every item shows its exact licence. Open source items (GPL, MIT, BSD, CC0, CC-BY and similar) say so; freeware items (OB-Xd 2) are free to use but closed. Most of the sounds are public domain (CC0). The Salamander Grand Piano (CC-BY-3.0) and MuldjordKit (CC-BY-4.0) ask for a credit when you release music made with them: the credit line is shown in the item's Details.

Left out on purpose: the x42 plug-ins (macOS builds are sold), LSP (no macOS builds) and Helm (no build for current Macs). The Store tab lists them with the reason, and leaves out anything whose download needs an account.

What has and has not been tried

The downloader, the unpacking limits, the link checks and uninstall are covered by tests that run against archives built on the test machine and a download server on the same computer; the real catalogue items have not been installed from the internet in those tests (a test that does one real download exists, and runs only when asked). The Store has been used on an Apple Silicon Mac only, not on an Intel Mac. Two items (Odin 2 and Airwindows Consolidated) download a rolling pre-release build rather than a numbered release, and the licence labels of OB-Xd and Cardinal's bundled modules are still to be checked against the publishers' pages.

From a terminal

hypnomix store lists everything, hypnomix store search reverb searches, hypnomix store info surge-xt shows the exact download, and hypnomix store install surge-xt, uninstall and updates do the rest (--replace replaces copies the Store did not install; --unverified installs a download that has no fingerprint, after the command has refused it once and said why). HYPNOMIX_STORE_ROOT=/some/folder puts everything under that folder instead of your Library, for trying it out.

Adding an item

The list is hypnomix/store/catalogue.json. Copy an entry, fill in every field from the publisher's own page (never a mirror), say about how big the download is ("size": "190 MB": it sets the download limit), pin the publisher's sha256 whenever they give one, and run hypnomix store check and the tests. The catalogue is checked every time it is loaded: an id or name that is not safe as a folder name, a download that is not https, or a CC-BY licence without its credit line is refused. Only add things that download without an account, and name the project or organisation, not a person (a licence's required credit goes in the credit field).
