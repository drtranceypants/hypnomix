Mac only for now. The Store installs into the Mac's Library and Music folders. On another system the Store tab and the hypnomix store command say so plainly and install nothing; the free plug-ins can still be downloaded from their publishers' own pages (each item's Details links to it).

The Store tab in the app is a short, checked list of free plug-ins and sounds, each downloaded from its publisher's own page or GitHub releases. Search it, filter it by kind (effect, instrument, synth, drum kit, sample pack, SFZ instrument), format (VST3, AU, CLAP, LV2, VST, SFZ, WAV, FLAC) and licence, open an item's Details to read its licence and see exactly where it comes from, then press Install. In the DAW view, the browser's Store place opens it too.

What is new

  • More items: the Store now lists 69 (24 effects, 12 synths, 6 instruments, 13 SFZ instruments, 13 drum kits and 1 sample pack; 68 open source and 1 freeware). The additions are instruments that play per-note expression, small free percussion sets, and gap-filling effects: an equaliser, a compressor, a mastering chain, noise reduction and a pitch shifter.
  • The MPE mark and filter, described below, and a Note in each item's Details for things worth knowing before you install.
  • A download that is itself an installer package is now handled (see Installer packages), and big archives get the time they need to unpack (see step 3 below).

MPE

MPE (MIDI Polyphonic Expression) lets every note you hold carry its own pitch bend, pressure and slide, instead of sharing one of each with all the other notes. It only does something when your controller sends it and the instrument has MPE switched on, which most instruments leave off until you turn it on.

Items whose maker documents MPE carry a small MPE mark on their card, and the MPE box beside the other filters shows only them (in a terminal, hypnomix store list --mpe). Open Details and the MPE line says, in one sentence, what the maker documents and where it is switched on in that instrument. The mark means "the maker says so", not "heard here": where a maker only hints at it (Dexed's release notes call its support "initial", and there is no page on how to switch it on), the sentence says so. An item that adds MPE to a keyboard that lacks it, a small MIDI plug-in, is marked too, and says that your DAW has to pass its output on.

What happens when you press Install

  1. The newest download is found: for GitHub items, the newest release file that matches the catalogue; for the others, the publisher's fixed link.
  2. It is downloaded over HTTPS only (a redirect to anything else is refused, and a token is never sent on to another site). When there is a sha256 fingerprint to check against, the download is checked against it, and a mismatch deletes it. See Is it verified? below. The download also has limits: it may not be much bigger than the size the catalogue states (or 2 GB when none is stated), the whole install must finish within four hours, the disk must have room for the download, its unpacked copy and the installed copy, and a Cancel button stops it.
  3. It is unpacked (zip, tar, 7z, or a disk image opened read-only and closed again). Paths, and links, that would land or point outside the folder are refused, disk images included, and so is an archive that unpacks to far more than it weighs (more than 100 times its size, 20 GB in all, or 100,000 files; what an unpack writes is measured about once a second while it runs, and once more when it ends, so a fast one can land before it is stopped; the disk-space check before the download keeps that bounded). On a Python that lacks the safe-extraction filter (older than the security releases of 3.11, in a terminal), a tar archive with any link in it is refused outright. Nothing in the download is run. How long an unpack may take depends on how big the download is: 15 minutes, plus one second for every 2 MB (counting the download, or what it says it holds if that is more), and never more than 2 hours. A 100 MB download gets 16 minutes, 3 GB gets 40 minutes, and anything from about 13 GB up gets the 2 hours. Cancel stops it at any moment, and if the limit is reached the message says how long it was allowed, that nothing was installed and that the downloaded file was deleted, so you can try again when the computer is quiet.
  4. Plug-ins are copied into ~/Library/Audio/Plug-Ins/ (VST3, Components for AU, CLAP, LV2). Sounds go into ~/Music/Hypnomix Library/ (Drum Kits, Sample Packs, SFZ Instruments), one folder per item.
  5. The app writes down every file and folder it put there, so Uninstall removes exactly that and nothing else, and Update replaces it.

Is it verified?

Each item's Details says how its download can be checked, before you press Install:

  • Pinned: the catalogue holds the sha256 the publisher gave: one item so far (Membrum, whose repository publishes a release for every one of its plug-ins, so the Store pins the one file instead of asking for "the latest").
  • GitHub's fingerprint: the items downloaded from GitHub releases are checked against the sha256 GitHub publishes for the release file, when it publishes one. That catches a damaged or swapped download; it does not prove the publisher's account was not compromised.
  • Not verified: items whose publisher gives no fingerprint carry a not verified tag. Any download with nothing to check it against, whichever item, is not installed until you confirm a second time, in plain words, that it is not verified: a button in the Store tab ("Install anyway (not verified)"), --unverified on the command line, and the same words on the Assistant's approval card.

The honest list. When the release files were read on 26 November 2026, 39 of the 69 items had no fingerprint published for their download: Vaporizer2, ChowMultiTool, AIDA-X, Ildaeil, Surge XT, Odin 2, sfizz, ChowKick, Dragonfly Reverb, CHOW Tape Model, ChowMatrix, BYOD, Valentine, Wolf Shaper, the FreePats sets (Synthesizer Percussion, World Percussion, ColomboADK, Hang, Timpani, Glass), MuldjordKit, Big Rusty Drums, Black And Blue Basses, Meatbass, Gogodze Phu Vol I, Frankensnare, Unruly Drums, Swirly Drums, The Hat With The Phat, Bear Sax, War Tuba, String Cyborgs, Horse Pulse, and the fixed links to the Salamander Grand Piano, VSCO 2 CE, the Versilian Community Sample Library, Body Percussion, Naked Drums and DRSKit. Three of those last (Body Percussion, Naked Drums, DRSKit) are snapshots of a maker's repository at one fixed commit rather than a numbered release, and their real download size is not stated. A publisher can add a fingerprint to a later release, or drop one, so Details tells you the truth at the time you install; this list is only what was true on that day.

Installer packages

Many publishers only ship an installer package (.pkg), or a disk image or archive that holds one. The store never runs those for you. It downloads the file and checks it, finds the package (inside a disk image or archive, or, when the maker publishes NAME.pkg directly, the download itself), keeps it in its installers folder marked as downloaded from the internet (so that macOS checks it when it opens), records it, opens it in Apple's Installer, and you read it and click through it yourself. A file that is named like a package but does not start the way one does is refused and nothing is kept. If macOS cannot be told that the file came from the internet, it is still kept and recorded, but the Store does not open it for you (the note says so): use Show installer to try marking it again, or open it yourself. An installer package puts files outside your home folder and often installs for every user of the Mac, so it asks for your password, which is why the Store never does it for you. Show installer opens it again later; Disk care clears kept installers after 30 days (sooner on a nearly full disk), and then the button is gone until you install again. Remove those plug-ins with the publisher's instructions; Forget only deletes the kept installer. Not tried: opening a real publisher's installer package through macOS's check on this build.

An item whose publisher's site doesn't allow automatic downloads gets a Get it from button that opens its download page instead.

Notes

An item's Details can carry a Note (the card shows a small dashed "note" tag): a sentence or two to read before you install. The notes say things like "this is a nightly build, not a numbered release", "the maker does not sign this build, so macOS asks you to approve it once in System Settings, Privacy and Security", "this installer installs for all users and asks for your password", "a big download" or "the maker calls the Mac build untested". They come from the makers' own pages, not from HypnoMix testing the item.

When something is already there

If a plug-in with the same name is already installed and the store didn't put it there (you installed it yourself, say), the install stops and lists what is in the way. Replace them goes ahead after you confirm, and moves the old copies to ~/.hypnomix/store/trash rather than deleting them at once (Disk care clears the trash after 60 days). Disk care clears that trash, unfinished downloads and old kept installers quietly, like its other caches: trash after 60 days, kept installers after 30, leftovers of a stopped download after 2 (all sooner when the disk is nearly full).

Uninstall

Uninstall removes exactly the paths the app wrote down, and only if each is one item directly inside a plug-in or sounds folder (compared by real path, so a link cannot lead it elsewhere, and a whole plug-in folder is never removed). If the list has been edited by hand to point anywhere else, nothing is removed and it says so.

After installing

Your DAW finds new plug-ins the next time it starts or rescans them. If the HypnoMix DAW's engine is connected the store asks it to rescan, but its MCP surface has no rescan tool yet, so the app tells you to rescan in the DAW's Plugin Manager or restart it. SFZ instruments and drum kits play in sfizz, which is also in the store: load the .sfz file from the item's folder.

Licences

Every item shows its exact licence. Open source items (GPL, MIT, BSD, CC0, CC-BY and similar) say so; freeware items (OB-Xd 2) are free to use but closed. Most of the sounds are public domain (CC0). The Salamander Grand Piano (CC-BY-3.0) and MuldjordKit (CC-BY-4.0) ask for a credit when you release music made with them: the credit line is shown in the item's Details.

Left out on purpose: the x42 plug-ins (macOS builds are sold), LSP (no macOS builds), Helm (no build for current Macs), stand-alone applications, anything that needs an email form or an account to download, and free editions of products whose makers sell a paid edition under the same name. The Store tab lists them with the reason.

What has and has not been tried

The downloader, the unpacking limits, the link checks and uninstall are covered by tests that run against archives built on the test machine and a download server on the same computer; the real catalogue items have not been installed from the internet in those tests (a test that does one real download exists, and runs only when asked). The Store has been used on an Apple Silicon Mac only, not on an Intel Mac. Three items (Odin 2, Airwindows Consolidated and Shortcircuit XT) download a rolling build rather than a numbered release, and the licence labels of OB-Xd and Cardinal's bundled modules are still to be checked against the publishers' pages. The newest items were checked against the makers' own release pages (the file names, sizes and fingerprints above), but no installer package, disk image or sound set among them has been downloaded or installed by these checks, and nothing has been heard: "the maker documents MPE" is the maker's word. The bare-package handling and the scaled time limit are covered by tests with a stand-in download server and a stand-in clock; the time limit has not been reached by a real multi-gigabyte unpack.

From a terminal

hypnomix store lists everything, hypnomix store search reverb searches (--kind, --format, --open, --licence and --mpe narrow it; hypnomix store list --mpe lists the MPE items), hypnomix store info surge-xt shows the exact download, what the maker documents about MPE and the item's note, and hypnomix store install surge-xt, uninstall and updates do the rest (--replace replaces copies the Store did not install; --unverified installs a download that has no fingerprint, after the command has refused it once and said why). HYPNOMIX_STORE_ROOT=/some/folder puts everything under that folder instead of your Library, for trying it out.

Adding an item

The list is hypnomix/store/catalogue.json. Copy an entry, fill in every field from the publisher's own page (never a mirror), say about how big the download is ("size": "190 MB": it sets the download limit), pin the publisher's sha256 whenever they give one, add a "note" for anything a person should know before installing (a nightly build, an unsigned build, an installer for all users), set "mpe": true with a one-sentence "mpe_note" only where the maker documents MPE (and leave both out otherwise), and run hypnomix store check and the tests. The catalogue is checked every time it is loaded: an id or name that is not safe as a folder name, a download that is not https, or a CC-BY licence without its credit line is refused. Only add things that download without an account, with a licence that has no time limit, and name the project or organisation, not a person (a licence's required credit goes in the credit field). Describe an item by what it does, not by naming a paid product or a piece of hardware it resembles.
