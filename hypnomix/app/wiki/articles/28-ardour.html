What works today. hypnomix reads sessions saved by Ardour 3 to 9: tracks and buses, regions (with the way Ardour layers them: upper regions cover lower ones), fade curves, gain envelopes, multi-channel regions, plug-ins and automation. It renders each track from the session without opening Ardour, and scan runs the same checks as on a REAPER project: missing files, clicks at region edges, level jumps at comp cuts, vocal pitch and doubles, plug-ins switched off, the source recordings, boosted noise and "is this deliberate?" questions.

Fixes are written into a new snapshot. hypnomix fix "hypnomix-out/scan/Song" --approved --out "Song (fixed).ardour" writes one new .ardour with the changes you approved, next to your session file, inside the same session folder. That is where Ardour keeps its own snapshots, and where it looks for the session's audio (interchange/<session>/audiofiles), so the new file finds the same recordings; nothing is copied or moved, and your original is never touched. It works on every Ardour version hypnomix reads (sample times before Ardour 7, superclock and beat times after).

What it can write: region fades in and out (as a curve; shape=linear, power or slow in the decision note; a fade that is already longer is left alone), region gain, a dip over a spike (a quick turn-down in the region's gain envelope, so your fader and automation stay yours), the eased level after a comp cut (a gain envelope on the region that starts a little quieter and returns to normal; method=item sets the region gain instead), and fader, pan and mute on a track. A fader, pan or mute that already plays automation is refused. Track names and order, vocal stacks, timing nudges (each timing finding says how to do it by hand in Hypnomix or Ardour: split around the hit and slide it, or stretch the region) and sidechain stay by hand for now, and so does tuning (those make new audio you bring in). hypnomix handoff turns the by-hand list into a checklist in Ardour's words, with a MIDI marker file and a CSV to import.

Safety. It refuses when the session was saved after the scan, when the output exists, or on protected tracks. Each approved finding is found again by its region; one that is not there is skipped and said so. The new file is checked: same tracks, buses, regions, positions and lengths, ids unique, fade and envelope times well-formed, regions inside their files, and nothing outside the approved edits differs. A file that fails is renamed "(BROKEN, do not open)". Then fix reads it back, lists exactly what changed and measures the clips again.

Written and re-read by hypnomix; not yet opened in Ardour. Ardour is not installed where this was built, so nothing has been opened in a running Ardour. The reader was tested on real Ardour 3, 8 and 9 session files; the writer on synthetic sessions in both time formats. Please check in Ardour, and tell us what you see:

  • the new snapshot opens without a warning (Session > Open, or the snapshot list);
  • the audio is found (no missing-files dialog);
  • fades and gain are as written: the listed regions show the fade lengths and curve, the gain, and the envelope dips;
  • pan direction is the way round you expect (azimuth 0 is left), if you approved a pan move;
  • the trim knob is where it was (the fader move leaves it alone).

Findings that make new audio (tuning, de-hiss, de-ess) work as for any DAW. Driving the open session with Ardour's own plug-ins is next on the roadmap. The reader's renders also haven't been compared with Ardour's own export.

Mastering in Hypnomix. In Hypnomix (our build of Ardour) chain master --ardour builds the mastering chain in the open session over MCP: ACE High/Low Pass Filter, ACE EQ, ACE Compressor, Hypnomix Utility (gain, width, mono, bass mono with a phase-coherent crossover, polarity, DC filter) and Hypnomix Limiter (look-ahead, holds a true-peak ceiling measured with 4x oversampling), every value dialled in from your bounce. Not there yet: a saturator, --verify, and chain strips. If a step fails part-way, the build is taken back out: what this run added is removed, your own plug-ins are switched on again (with --existing bypass they are only switched off once the whole chain is in), and the message says what was undone. A stage that could not be built or set reads NOT BUILT or NOT SET in the table, a value the plug-in's range had to move reads CLAMPED with the planned and the set value (for gain, ceiling, threshold and make-up, which change the loudness, it also counts as not set), and the command exits with an error. After an incomplete chain, take the plug-ins it added off the master strip before running it again, or it would build the chain twice (the command refuses to run on top of them unless you pass --existing). The engine's address must be on this computer. This was tried against a stand-in for the engine's MCP surface, not against the running engine.

$ hypnomix chain master "Song bounce.wav" --target -14 --ardour --existing bypass   # the chain on the master bus

Bring a Live set across: hypnomix als2ardour. hypnomix als2ardour "Song.als" "Song (Hypnomix)" makes a new session folder from a Live set; the set and its project folder are only read, and the new folder must be somewhere else. It is built in a hidden folder next to it and renamed into place at the end, so a failure leaves nothing half-made (a hidden .NAME.tmp-… folder left by a force-quit can be deleted). What comes across: every track with its name, order and colour; the Arrangement's clips as regions in the same places, with their clip gain, fades (Live's short edge fades too), switched-off clips muted and looped clips laid out one region per pass; faders, pans, track on/off (as mute), solo and their automation; return tracks as buses with an aux send from each track at the same level (pre or post as in Live); group tracks as Ardour route groups, with a bus the group's tracks feed when the group has its own devices, fader, sends or automation; the tempo and time signature, and tempo changes as tempo points (a tempo ramp becomes a run of small exact steps, so the map agrees with itself). The audio is copied into the session (one mono file per channel, as Ardour's own import does; a file at another sample rate is resampled), so the session never depends on the Live project. MIDI clips bring their notes, but not the instrument.

Warped clips. A clip whose warp markers make one straight line plays at one speed: at the set's tempo (most recorded audio) it comes across exactly; at another speed it comes across as a stretched copy of the file (Rubber Band, pitch kept), and the report says so. Clips whose warp markers bend the timing are not carried as warps yet (Ardour has no warp maps; that is the next step): they are placed along the straight line from their first to last marker and listed with how far that drifts.

What it never guesses. Devices and plug-ins are not carried: IMPORT-REPORT.md, next to the new .ardour, lists every track's Live devices (and the main track's), the take lanes and Session clips left behind, missing files, resampled files, samples from outside the project folder, and the Live settings that change what you hear and are not carried: a clip's transpose, the Re-Pitch warp mode, track delay, split stereo pan, clip grooves, the crossfader's A/B side, fade curve shapes and crossfades, MIDI note probability and controller envelopes, time-signature changes and locators. The new session is built next to the folder you name (inside it, if it is an empty folder you made) and moved into place only when it is complete, so a failure leaves nothing half-made and a folder that already exists empty stays the same folder. Only real audio files are copied (the file's own contents are checked, not its name), and a set from a newer Live than hypnomix has been tested with prints one warning line. Until the processing is rebuilt the session plays the raw clips through the faders, so it will not sound like the Live mix. Live's pan law differs from Ardour's off-centre, and track names lose the characters Ardour does not allow (| : / ? * become _). A track inside a group whose output Live sends straight to the Main track skips the group here too. Copied files and MIDI files always get names of their own, so two takes called Vox.wav and vox.wav never overwrite each other.

How it was checked. On a real 31-track set (883 regions, groups, returns, MIDI): the new session opened in Hypnomix and every region was where the set has it (read back over the Hypnomix MCP); a headless Hypnomix loaded and saved it and it read back the same (MIDI positions within a microsecond); and hypnomix project --render of the new session matched hypnomix render of the set track for track: same timing to the sample, same level within 0.001 dB. Played by the Hypnomix engine itself (hypnomix9-export, the lead vocal alone), the new session matched hypnomix render of the set to the sample, residual 97 dB down. Not yet checked: that it sounds right when played in the app, clip volume envelopes against Live's own playback, and a set with tempo ramps opened in Hypnomix itself (the written tempo map was only checked against Live's own integral; the report names the ramps and how far a point inside one can be off).

$ hypnomix project "Song/"               # what is in the session: tracks, buses, regions, plug-ins, automation
$ hypnomix project "Song/" --render      # render every track the way Ardour layers the regions
$ hypnomix scan "Song/"                  # the first pass: one review list (or point at Song.ardour)
$ hypnomix review "hypnomix-out/scan/Song" --serve   # play A and B, approve or skip
$ hypnomix als2ardour "Song.als" "~/Hypnomix/Song"   # a Live set into a NEW session folder; read IMPORT-REPORT.md

Ardour can stay open while you scan; nothing is written next to your session. A fix writes a new snapshot beside it; open that in Ardour when it is done. Any way of driving hypnomix works with Ardour: choose your setup.
